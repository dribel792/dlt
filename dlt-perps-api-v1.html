DLT Perps API v1

Partner integration specification · REST + WebSocket (FIX on request) · Draft v1.0 · 2026-10-26

The DLT Perps API gives exchanges, brokers and fintech apps everything needed to offer their users a complete perpetual-futures trading experience — markets, leverage, long/short, live liquidation price, funding, TP/SL, positions, PnL, equity — on EU-regulated securitized perps.

The API is designed so that a team that has built a perps UI before will find nothing unfamiliar: same objects, same field names, same screen-to-endpoint mapping. Where the regulated wrapper requires something a crypto perps API does not have (client onboarding, appropriateness, KID disclosure, trade confirmations), it is a separate, clearly marked module.

1. Perp concepts in this API

Every perp concept your UI already knows exists here, with the same name:

Perp conceptIn this APINotes
Market / symbolBTC-USDC, ETH-USDC, XAU-USDC …One market per underlying. Long and short are both traded in the same market.
Mark pricemark_priceThe reference market price of the underlying (designated reference venue, e.g. Bybit BTCUSDT perp). Drives PnL, liquidation and charts.
LeverageleverageChosen per order from the market's leverage tiers (§4). Like on any perp venue, effective leverage moves with the mark price and is always served live.
Margin modeisolatedEvery position is isolated: margin = what the user paid for the position; max loss = margin. (Cross margin: see §7 note.)
Initial marginmarginThe cost of the position. No separate margin account, no margin calls.
Liquidation priceliq_priceFixed at entry, moves only with funding (8h). When mark touches it, the position is liquidated (§9).
Fundingfunding_rate, funding_paidSame 8h cadence and direction as perp funding. Settled inside the position (it adjusts the position's entry basis and liq price) rather than as a cash transfer — the API reports it as a USDC amount per position, exactly like perp funding history.
Position modeHedge modeLong and short positions in the same market are independent (position_side). There is no netting.
OrderbookReference book + executable quotesThe displayed book is the reference market. Executable prices for every tier come from the quotes channel, already converted into perp entry/exit prices (§5).
One position per leverage tier. A position is identified by market + side + tier. Adding size at the same tier adds to that position (same liq price, averaged entry). Opening at a different leverage opens a second position in the same market; GET /positions?group=market returns the aggregated, single-row-per-side view most perp UIs show, with the legs underneath.

2. Conventions

Environments

Production   REST  https://api.dlt-perps.eu/v1          WS  wss://stream.dlt-perps.eu/v1
Sandbox      REST  https://api.sandbox.dlt-perps.eu/v1  WS  wss://stream.sandbox.dlt-perps.eu/v1
FIX 4.4      on request (order entry + market data), same semantics as REST/WS

Hostnames are placeholders until production DNS is assigned.

Authentication

Partner API keys are issued per environment, scoped (read, trade, accounts, funds) and IP-allowlisted. Requests are signed with HMAC-SHA256:

DLT-API-KEY:     pk_live_3f9a…
DLT-TIMESTAMP:   1793007600000                       # ms since epoch, ±5 s of server time
DLT-SIGNATURE:   hex(hmac_sha256(secret, timestamp + method + path + query + body))
DLT-ACCOUNT:     acc_7Q2M9KX1                        # required on account endpoints

WebSocket: authenticate with {"op":"auth","key":…,"ts":…,"sig":…} after connect; then subscribe to account channels with an explicit account list ("accounts":["acc_7Q2M9KX1", …]) or "accounts":"*" for a partner-wide firehose.

Account model

The partner has one partner key. Each of the partner's end users is a DLT account (acc_…), opened through the API (§3) — the end user is a client of record of DLT, so balances, positions and records are held per account, never only in an omnibus. All trading and account calls act on one account, selected by header:

DLT-ACCOUNT: acc_7Q2M9KX1         # end-user account the call acts on

Endpoints are marked public (no auth), account (partner key + DLT-ACCOUNT), or partner (partner key, partner-level data across accounts).

Formats

  • Prices, sizes and amounts are decimal strings. Timestamps are ms since epoch, UTC.
  • Size can be given in any of three units, everywhere: qty (underlying units, e.g. BTC), margin (USDC the user commits), notional (USDC exposure = qty × price). Responses return all three.
  • All mutating calls accept Idempotency-Key; replays within 24 h return the original result.
  • Lists paginate with limit (default 100, max 500) + cursor; time filters start/end.
  • Versioning in the path (/v1). Additive changes ship without notice; breaking changes get a new version and ≥ 6 months parallel run.

Rate limits

ScopeLimit
Public REST1,200 req/min per partner key (proxy and cache public data for your users — do not fan out 1:1)
Account REST60 req/s per partner, 10 orders/s per account
WebSocket20 connections per partner, 500 subscriptions per connection; ping every 15 s

X-RateLimit-Remaining on every response; 429 with Retry-After when exceeded.

3. Accounts & onboarding

A user must have an active account with a passed appropriateness assessment before the first order. The partner collects KYC as part of its own onboarding and hands it over; DLT does not re-contact the user.

GET/orders · /orders/{id} · DELETE/orders/{id} · DELETE/ordersaccount

Open orders, single order with its fills, cancel one, cancel all (optionally per symbol). GET /orders/history for closed orders.

POST/positions/{id}/closeaccount

Convenience: market-close full or partial ({"qty":"0.500"}). Equivalent to an action:"close" order.

POST/positions/{id}/tpslaccount

Set / modify / remove TP and SL on a position (full or partial size). Both trigger on mark price and execute as market close with slippage_bps. Removed automatically when the position closes or is liquidated.

{"take_profit":{"trigger_price":"92500.00","qty":"all"},
 "stop_loss":{"trigger_price":"88600.00","qty":"all"}}

POST/positions/{id}/leverageaccount

Change leverage on an open position. Executed as one atomic operation — the position is moved to the target tier at pinned quotes: realized PnL, fees and the new liq price are returned in one response (two fills). Lowering leverage this way is also the equivalent of "add margin".

{"leverage":"20","mode":"keep_qty"}     // keep_qty (adds/frees margin) | keep_margin (changes qty)

POST/accounts/{id}/killpartner

Emergency: cancel all orders and optionally close all positions of an account ({"close_positions":true}).

FieldDefinition
marginWhat was paid for the open size (average-cost, excl. fees)
position_valueCurrent value at mark: what the position is worth right now
unrealized_pnlposition_value − margin; roe_pct = uPnL / margin

Tokens transferred in from outside: DLT only knows the entry price of fills it executed. For transferred-in size the partner may register a cost basis (POST /positions/{id}/basis {"entry_price":…,"qty":…} → pnl_basis:"client_provided"); without it, entry_price/unrealized_pnl/roe_pct are null and the UI shows position value only. In the normal partner flow everything is traded via DLT and this never arises.

GET/balanceaccount

{"currency":"USDC",
 "wallet_balance":"1439.18",           // cash
 "available":"1439.18",                // cash minus open-order reservations
 "position_margin":"3498.76",          // Σ margin of open positions
 "unrealized_pnl":"537.74",

Same arithmetic as a perp account in isolated mode: equity = wallet + margin + uPnL. Other cash currencies (EUR) appear as separate rows if enabled for the partner.

Cross margin. v1 is isolated-only. A cross-margin mode — open positions counted as collateral for new ones via a DLT margin account, with the same margin-ratio display perp users know — is planned as an optional module; it will add margin_mode:"cross", maintenance_margin and margin_ratio fields without changing anything above.

9. Liquidation lifecycle

  1. Trigger. Mark price touches liq_price of a tier. All positions at that tier are liquidated at once; open orders and TP/SL on them are cancelled. Public: market_status → tier_liquidated. Account: liquidations → triggered.
  2. Close price. The covering perp position is unwound; the close price is determined from the unwind (typically within minutes). liquidations → price_determined.
  3. Remaining margin returned. The remaining value is credited to the wallet — no liquidation fee, no insurance-fund contribution, never a negative balance: max loss is the margin.
  4. Re-entry. successor names the new tier at the same leverage, so the UI can offer one-tap re-open.
{"channel":"liquidations","account_id":"acc_7Q2M9KX1","ts":1793011300000,
 "event":"margin_returned","position_id":"pos_4KD1","tier":"BTC-LONG-86900",
 "qty":"1.150","trigger_price":"87986.25","trigger_ts":1793007699850,
 "close_price":"87980.10","margin":"3498.76","returned":"1242.12","realized_pnl":"-2256.64",
 "determination_doc":"…/rv/BTC-LONG-86900-20261026.pdf","successor":"BTC-LONG-85400"}
