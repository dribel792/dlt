Programme objective — a securitized perp The goal of this programme is to issue a security token that replicates the economics and user experience of perpetual-futures trading so completely that a user cannot tell the difference. Leverage selection, position sizing, open-ended (perpetual) holding period, continuous price tracking, carry/funding display, and liquidation mechanics are all designed to feel identical to trading a perp on a native crypto venue — but the instrument is a fully regulated, prospectus-based transferable security, not an OTC derivative. In one line: a securitized perp. The single product line described here is the Unlimited Perpetual Knock-Out Certificate.

Hard custody requirement. The token MUST be custodizable by a German qualified custodian — a Kryptoverwahrgeschäft-licensed institution (e.g., Tangany, Hauck Aufhäuser Lampe, Bankhaus von der Heydt). It is issued as a security token sui generis — a DLT-native transferable security following the Ondo / xStocks pattern — precisely so that it falls within the scope of a German qualified custodian's licence. Custody compatibility with a German qualified custodian is a non-negotiable design constraint for every Series.
Note to counsel: This document uses terminology from the cryptocurrency derivatives market in its illustrative worked examples (BTC, exchange perpetual mark price, funding rate, etc.) because the perpetual-future analogue is what informs the product's economic design. The programme expressly covers four asset classes (crypto, precious metals, equities, commodities); the crypto-specific mechanics are retained as the canonical baseline and the TradFi equivalents are described in the asset-class sections. Where crypto terms appear, plain-language explanations are provided inline. No prior knowledge of cryptocurrency markets is assumed. KEY FORMULAS

Key Formulas — Programme-Level

The deterministic formulas published in the base prospectus. Per-Series parameters (Reference Venue, Contract Size, Barrier at issuance, MMB%, Carry Settlement cadence) are fixed in the Final Terms. Worked-example numbers below use BTC as illustration; the same formulas apply across all asset classes (crypto perp reference; spot or perp reference for metals / equities / commodities).

F1. Certificate Value

The value of an Unlimited Knock-Out Certificate at any point in time is:

Long certificate: Certificate Value = (Reference Price − Knock-Out Barrier) × Contract Size Short certificate: Certificate Value = (Knock-Out Barrier − Reference Price) × Contract Size Where: Reference Price = the Series' Reference Price as defined in §3.1 / §3.1quinquies (crypto: venue perp mark price; metals/equities/commodities: 24/7 perp where available, else spot) Knock-Out Barrier = fixed at issuance per Series, adjusted at each Carry Settlement per F3 Contract Size = 1 / Multiplier (fixed in Final Terms) e.g., Multiplier 1,000 → Contract Size 0.001 BTC per cert

F2. Implied Leverage and PnL

Implied Leverage (current, live) = Reference Price ÷ (Reference Price − Barrier) PnL per 1-unit move in underlying = ± Contract Size × (1 unit) Worked example (long, BTC at USD 102,400, Barrier USD 92,160, cs 0.001): Certificate Value = (102,400 − 92,160) × 0.001 = USD 10.24 Implied Leverage = 102,400 / (102,400 − 92,160) = 10.0× PnL per USD 1 move = 0.001 × 1 = USD 0.001 per certificate (equivalent to holding 0.001 BTC)

Implied leverage drifts continuously as the Reference Price moves — identical to a perp position. The Series identifier encodes the Barrier, not the leverage (see Series Naming, F6).

F3. Barrier Adjustment — Carry Passthrough

At each Carry Settlement of the Series, the Barrier is adjusted to exactly mirror the carry cost (or credit) the issuer pays (or receives) on the hedge for that Series. Cadence and rate source are set per-Series in the Final Terms and follow the asset class (see Term Sheet "Carry mechanism" row).

At each Reference Venue carry settlement (crypto: typically every 8h; TradFi perp hedge: every 8h on the perp venue; TradFi spot/futures fallback: daily): For long certificates (issuer is long on the Reference / Hedge Venue): New Barrier = Previous Barrier + (Carry Rate × Reference Price at settlement) For short certificates (issuer is short on the Reference / Hedge Venue): New Barrier = Previous Barrier − (Carry Rate × Reference Price at settlement) Where Carry Rate is: Crypto perp Series → the Reference Venue funding rate Non-crypto perp-hedged Series → the perp-venue funding rate (preferred) Non-crypto spot/futures Series → ESTR/SOFR ± dividend yield or roll yield Sign convention: positive Carry Rate = longs pay shorts (the typical case). Bidirectional: a negative Carry Rate moves the long Barrier downward (Certificate Value increases — holder receives carry benefit).

F4. Knock-Out Event — Residual Value (Standard Calibration)

If the Reference Price equals or breaches the current Barrier (for long: from above; for short: from below), the Series terminates immediately. Holder receives:

Standard Calibration: Residual Value = max(0, (Reference Price at KO − Barrier at KO) × Contract Size) (short Series: signs reversed) In practice, for highly leveraged Series under Standard Calibration, the residual on a clean barrier-hit is zero or near-zero.

F5. Knock-Out Event — MMB Calibration (Perp-Parity)

The optional MMB Calibration brings the certificate's user experience into exact parity with perp liquidation mechanics: the Barrier is set at the point of zero-equity, and the holder additionally receives a fixed Maintenance Margin Buffer (MMB) cash payment on KO — mirroring how a perp exchange returns the maintenance margin remnant on liquidation.

MMB Calibration: Barrier at issuance = Reference Price × (1 − 1/Leverage) (zero-equity barrier — same algebraic relationship as Standard Calibration) Series Notional Value = Reference Price at issuance × Contract Size MMB Amount = MMB% × Series Notional Value (typical MMB% = 0.3% to 1.0%, fixed per Series) At KO event: Residual Value to holder = max(0, (Reference Price at KO − Barrier at KO) × Contract Size) + MMB Amount Worked example: 10× long BTC; Reference Price USD 102,400; Barrier USD 92,160: Contract Size = 0.001 BTC Notional Value = USD 102.40 MMB% = 0.5% MMB Amount = USD 0.512 per certificate Standard Calibration residual on KO (clean barrier hit): max(0, (92,160 − 92,160) × 0.001) = USD 0.000 MMB Calibration residual on KO: max(0, (92,160 − 92,160) × 0.001) + USD 0.512 = USD 0.512 The MMB Amount is the deterministic floor on the residual value at KO.

F6. Series Naming Convention

Format: [UNDERLYING]-[DIRECTION]-KO[BARRIER_IN_THOUSANDS]k-[VENUE] Examples: BTC-LONG-KO92k-BITMEX Long BTC, KO at ~$92k, BitMEX reference BTC-LONG-KO92k-HYPERLIQUID Long BTC, KO at ~$92k, Hyperliquid reference ETH-LONG-KO318k-DERIBIT Long ETH, KO at ~$3,180, Deribit reference XAU-LONG-KO2100-BYBIT Long Gold, KO at $2,100, Bybit XAU perp ref OIL-SHORT-KO95-OKX Short Oil, KO at $95, OKX perp reference AAPL-LONG-KO180-HYPERLIQUID Long Apple, KO at $180, Hyperliquid perp ref SPX-SHORT-KO5800-CME Short S&P 500, KO at 5,800, CME futures ref (fallback where no liquid index perp exists)

F7. Add-Margin Mechanism

Holders may deposit additional collateral to move the Barrier further from the Reference Price — reducing implied leverage and reducing the probability of KO. The issuer simultaneously deposits matching margin into the hedge so the hedge alignment is preserved.

Top-up of ΔC USDC by holder (long Series): New Barrier = Previous Barrier − (ΔC / Contract Size / Number of Certificates) Implied Leverage falls accordingly; KO probability falls. The mechanism is the only top-up mechanism offered; no continuous margin management, partial close-out, or cross-margining. See Q6 on CFD-reclassification analysis of the add-margin mechanism.

STRATEGIC CONTEXT — PROGRAMME-LEVEL QUESTIONS

Strategic Context

The following strategic-context questions are programme-level (they apply across the KO Certificate product line addressed in Sections 1–9 above). Each section states our working position and ends with the specific legal questions counsel is asked to determine.

S1

S1. Issuance Model — Security Token Sui Generis (Primary) + Optional Certificate

The instruments are intended to be issued primarily as security tokens sui generis — DLT-native transferable securities that do not derive their legal existence from a paper instrument or CSD book entry, but exist natively on-chain. This is distinct from "tokenized certificates" (where the certificate exists in paper/book-entry form and the token is a representation). The token is the security. The programme additionally supports parallel issuance as traditional bearer certificates (CSD-based, ISIN) for the same product Series; this is an optional capability per-Series.

Where both formats are issued for the same Series, the design intent is that conversion between formats is possible — a holder of the security token could in principle receive the bearer certificate equivalent, and vice versa. Whether this conversion right must be contractually embedded in the terms, or can be offered at the issuer's discretion as an operational service, is a counsel question.

Qualified custodian integration. The programme contemplates that each account opened with the issuer automatically establishes a corresponding custodial account with a qualified custodian (Tangany, or an equivalent regulated crypto custodian), so that all token holders have institutionally-administered custody from day one without a separate onboarding flow.

Legal questions for counsel — S1

Single prospectus for optional dual format: Can a single base prospectus cover Series issued (a) as security tokens only, (b) as traditional certificates only, or (c) both simultaneously, with the choice made per-Series at issuance?   2. S4

S4. Transferable Token Model — Ondo / xStocks Approach (Tokens Distributable w/o KYC)

The intended transfer model follows the approach pioneered by Ondo Finance (USDY, OUSG) and xStocks (tokenized equities): KYC is required to receive tokens directly from the issuer; once in circulation, tokens may be freely transferred between any wallet addresses on-chain — including unregistered wallets — without per-transfer KYC. The restriction applies at the point of issuance (issuer → user), not at the point of secondary transfer (user → user). This is the programme-level "tokens distributable w/o KYC" principle in the Term Sheet.

Transfer restriction model — issuer-gated at issuance, free in secondary: Issuer → User: KYC required. Only KYC-verified wallet addresses may receive tokens directly from the issuer (primary issuance / primary-market purchase). Smart contract enforces: issuer mint/transfer only to whitelisted addresses. User → User (secondary market): Transfers PERMITTED to any wallet address, including non-whitelisted. No smart contract restriction on peer-to-peer secondary transfers. The token is freely transferable once it leaves the issuer. Compliance maintained via: - KYC at primary issuance (AML/CFT check at point of first sale) - Issuer can freeze/blacklist specific addresses (sanctions compliance) - On-chain transfer history is publicly auditable - No ongoing KYC obligation for secondary-market transfers This mirrors how bearer securities work in traditional finance: Bearer bond issued to identified first holder; subsequent transfers between third parties are not gatekept by the issuer.

This model maximises secondary-market liquidity and concentrates the compliance burden at the issuance gate (the point the issuer controls). Ondo Finance has operated this model since 2023 across multiple jurisdictions without regulatory intervention. The key question is whether EU AML/CFT (AMLD6, MiCA, Transfer of Funds Regulation) imposes stricter obligations on secondary transfers than the US framework under which the Ondo precedent developed.

Legal questions for counsel — S4
  1. Issuer-gated primary / free secondary: Under EU AML/CFT (AMLD6) and MiCA, is a model where KYC is required only at primary issuance — but secondary transfers between any wallet addresses are unrestricted — compliant? Does the Travel Rule (FATF / EU Transfer of Funds Regulation) require KYC at every transfer step, or only at the point of entering/exiting the regulated issuer relationship?
  2. Bearer-instrument analogy: Can the free-transfer model be justified by analogy to traditional bearer securities? Is the sui generis security token treated differently from a bearer bond for AML/CFT purposes?
  3. Register of holders: For security tokens sui generis, is the issuer required to maintain a register of current holders? If secondary transfers are unconstrained and tokens may end up in unidentified wallets, how does this interact with the issuer's ongoing AML obligations?
  4. Sanctions compliance: If a token ends up in a wallet that is subsequently sanctioned, what obligations does the issuer have? Does the issuer need smart-contract freeze/seize functionality, and if so, can this function also reach tokens held in unregistered wallets?

S8. Token-Only Issuance — CFD Reclassification Risk?

If we issue products exclusively as security tokens (on DLT) and do not list them on any EU-regulated MTF or RM, does this affect their classification as "transferable securities" under MiFID II and under the CFD intervention?

Our position. Listing on an MTF is NOT required to maintain transferable-security status. The MiFID II definition (Article 4(1)(44)) requires that the instrument be "negotiable on the capital market" — which does not require listing on a specific venue. A security token freely transferable between wallets on a public blockchain is arguably "negotiable on the capital market" even without MTF listing. German KO/Turbo certs are routinely issued without exchange listing and traded OTC, retaining their transferable-security status.

Risk area — KO Certificate specifically. The KO Certificate's linear leveraged payoff is the most CFD-like of any product on the planned shelf. For equity / commodity underlyings, the German Turbo precedent is uncontroversial. For crypto specifically, if ESMA were to review an unlisted, OTC-traded leveraged token with crypto exposure, there is a non-zero risk of scrutiny of the transferable-security classification — and, if reclassified, the 2× retail crypto-CFD cap would bite.
Legal questions for counsel — S8

  2. CFD reclassification risk — KO Cert on crypto: For the KO Certificate specifically, issued as a security token, not listed on an MTF, traded OTC or on a DEX — is there any risk that ESMA or a national regulator classifies it as a CFD, triggering the 2× crypto leverage cap?
  3. Unlisted-certificate precedent: German issuers routinely issue KO/Turbo certs without exchange listing, distributed OTC. Has any German or EU regulator ever challenged the transferable-security classification on this basis?
  4. Prophylactic MTF listing: Would listing a single Series on a regulated exchange (even at minimal volume) be sufficient to establish transferable-security precedent for the entire programme, including token Series not separately listed?

Open Legal Questions for Counsel

The following questions require legal determination prior to or during prospectus drafting.

Question 1 — Financing Rate Formula Disclosure
What level of specificity is required in the prospectus for the barrier adjustment formula, and what flexibility does the issuer retain to update the formula?
The barrier adjustment formula references the Reference Venue's funding rate (rather than SOFR+spread). The formula is deterministic: New Barrier = Previous Barrier + (Funding Rate × Mark Price). We need to understand: (a) whether the base prospectus may define the venue class (BitMEX / Bybit / Binance / Kraken / OKX / Deribit) and leave the specific Reference Venue to per-Series election in the Final Terms (per Section 3.1bis); (b) what happens if the Series' Reference Venue ceases to publish a funding rate or is unavailable — fallback provisions or Series Termination at Fair Value; (c) whether the PRIIPS KID performance scenarios remain valid when the barrier adjustment depends on a variable funding rate.
Question 2 — Issuance Model: Fungible Series and Tap Mechanism
Can the issuer issue additional certificates into an existing series after the initial issuance date ("tap"), and does this require additional disclosure?
When demand exceeds the initial issuance volume for a series, we need to issue additional certificates with identical terms into the same series (same barrier, same ISIN). We need to confirm: (a) the series model qualifies as a transferable security; (b) tap issuances under identical terms do not require a new Final Terms or prospectus supplement; (c) the minimum issuance size per series (if any) for securities classification to hold.
Question 6 — Add-Margin Mechanism: CFD Reclassification Risk
Does the ability for holders to deposit additional collateral to reset their barrier constitute individual negotiation of terms, and does it create CFD reclassification risk?
The add-margin mechanism (Section 4.5) allows holders to move their barrier further from the mark price. Key concerns: (a) does the individual top-up transaction constitute individual negotiation of terms, defeating transferable security classification? (b) Could it be structured as a conversion into a new series? (c) Does the ability to contribute additional funds bring the instrument within MiFID II Annex I Section C(9)?
Question 7 — High-Leverage Tier (20×–30×) and Product Intervention Risk
Does inclusion of 20×–30× initial leverage tiers create material product intervention risk in target EEA jurisdictions, given cryptocurrency underlyings?
We need counsel to assess: (a) the current regulatory temperature in Germany, Austria, and the Netherlands regarding high-leverage crypto certificates; (b) whether a tiered access approach (e.g., 20×+ available only to professional clients or clients who have passed an enhanced appropriateness test) would be prudent; (c) whether the PRIIPs KID adverse performance scenario for a 30× cryptocurrency certificate adequately satisfies current investor protection standards.
Question 9 — Sui Generis Security Token: Custodian Compatibility
Does a sui generis security token representing the rights of a Knock-Out Certificate qualify for custody by a German Kryptoverwahrgeschäft-licensed custodian?
We request confirmation: (a) that a sui generis token constitutes a Kryptowert within KWG §1(11) S.4 and is within the scope of the Kryptoverwahrgeschäft licence; (b) that a Kryptoverwahrgeschäft-licensed custodian may hold such tokens without a separate Depotgeschäft licence; (c) BaFin's current position on sui generis security tokens as transferable securities under WpHG; (d) whether absence of a statutory register creates any gap in the chain of legal title.
Question 11 — BitMEX Mark Price as Benchmark: EU Benchmarks Regulation
Does the use of the BitMEX perpetual mark price as the reference price for the certificate constitute use of a "benchmark" under the EU Benchmarks Regulation (BMR, EU 2016/1011), and if so, what are the consequences for the issuer and distributor?
The BMR prohibits EU-supervised entities from using a benchmark in a financial instrument unless the benchmark is administered by a BMR-registered or recognised administrator. BitMEX is a non-EU exchange and its mark price may not be a BMR-registered benchmark. If the BitMEX mark price is a "benchmark" under the BMR, the issuer (and potentially the distributing MiFID II firm) may be prohibited from using it without an applicable BMR exemption or transitional provision. We need counsel to advise on: (a) whether an exchange-calculated mark price (a composite of recent trade prices and an index) constitutes a "benchmark" under the BMR Art. 3(1)(3) definition; (b) if yes, whether any exemption applies (e.g., the regulated exchange exemption under BMR Art. 2(2)(c)); (c) if no exemption applies, what the practical options are (substituting a BMR-registered index; obtaining a BMR recognition; relying on a third-country transitional provision).
Question 12 — Funding Rate Passthrough: Bidirectional Barrier Adjustment and CFD Reclassification
Does the bidirectional barrier adjustment (barrier decreasing when funding is negative, constituting an effective credit to the holder) create any risk that the instrument is reclassified as a CFD or as an instrument with "bilateral financial obligations" under MiFID II?
Financing could be modelled as unidirectional (always a cost to the holder); in the current design the barrier adjusts in both directions to mirror the exchange funding rate. When funding is negative, the barrier decreases — the certificate holder receives a benefit equivalent to the funding payment they would have received as a perp long. The instrument's daily value change now depends on a bilateral market-determined rate (the BitMEX funding rate), not just a fixed cost schedule. We need counsel to advise on: (a) whether the bidirectional adjustment affects the transferable security classification; (b) whether it constitutes a "contingent liability transaction" under ESMA guidance; (c) whether the instrument can still be described as a security whose value depends only on the mark price, given that the barrier (and therefore the value) also depends on the funding rate; (d) whether the PRIIPS KID cost disclosure methodology changes when costs can be negative.
Question 15 — Maintenance Margin Buffer (MMB) Calibration
Is the Maintenance Margin Buffer (MMB) Calibration compatible with (a) the transferable security classification under MiFID II Art. 4(1)(44); (b) the PRIIPs cost disclosure methodology; (c) the European Prospectus Regulation Final Terms structure; and (d) any specific disclosure required in the KID and marketing materials?
The MMB is a fixed, pre-defined, deterministic cash payment specified in the Final Terms at issuance, paid to the holder at KO in addition to the standard residual value. Its purpose is to bring the user experience into exact parity with perp liquidation mechanics. We believe: (a) the MMB does not introduce contingent liability or holder-issuer netting, so it does not affect transferable security classification; (b) the MMB should be disclosed as a component of residual value at KO, not as a separate cost in the PRIIPs cost methodology; (c) the MMB amount can be specified per-Series in the Final Terms without requiring a base prospectus supplement; (d) the marketing materials may describe the MMB as "your remaining margin returned at liquidation" to make the perp-parity feature plainly understood by the target user. We need counsel to confirm or correct these views.
Question 16 — Per-Series Reference Venue Election (Multiple Venues Across Series)
Does the per-Series Reference Venue election framework — with the same underlying issued in parallel Series referencing different venues (e.g., BTC-LONG-KO92k-BITMEX alongside BTC-LONG-KO92k-BYBIT) — create any specific PRIIPs comparison issue, MiFID II suitability/appropriateness consideration, or Prospectus Regulation Final Terms drafting concern?
We believe per-Series election is a routine prospectus-level structural choice that does not require any special disclosure beyond clearly identifying the Reference Venue in the Series identifier and Final Terms. We need counsel to confirm: (a) the per-Series venue election structure is compatible with the Prospectus Regulation; (b) the KID for each Series may be venue-specific without creating a comparative-disclosure obligation across Series; (c) the appropriateness test is conducted per-Series and does not require the distributor to compare venue risk profiles for the holder; (d) there is no fallback obligation requiring the issuer to substitute a Reference Venue mid-life if a Reference Venue becomes unavailable (we propose a defined "Venue Disruption Event" provision in the Final Terms with a "Series Termination with Fair Value Payment" remedy — see also Question 1 on financing rate disclosure).
Question 17 — Multi-Asset Underlying Extension: Regulatory Perimeter
Does the extension of the programme to cover four asset classes (crypto, precious metals, equities, commodities) under a single base prospectus create any product-classification, prospectus-disclosure, or product-intervention issue compared with a crypto-only programme?
We have assumed in §2.1 and §3.1quinquies that the asset-class extension is structurally neutral — the same instrument (Unlimited Perpetual Knock-Out Certificate) is issued, with the same payoff formula, the same Knock-Out Barrier mechanism, the same PRIIPs Category 3 classification — across all four classes; only the Reference Price source and the hedge venue universe differ. We need counsel to confirm: (a) a single base prospectus covering all four asset classes is acceptable to FL FMA (and to NCAs in DE/AT/FR/IT/ES/NL after passporting), or whether asset-class-specific base prospectuses are required; (b) whether any of the four classes attracts asset-class-specific product intervention measures (in particular: ESMA's CFD intervention for crypto retail, any commodity-specific national rules in DE/IT/FR); (c) whether the BMR analysis (Question 11) needs to be repeated separately for each Reference Price source (LBMA Gold Price, CME spot, primary listing exchange close, index provider published level) and whether the BMR posture differs from the crypto venue mark price; (d) whether the issuer's hedge book diversification across asset classes (crypto exchanges + LBMA bullion banks + prime brokers + futures FCMs) creates any disclosure or supervisory consolidation issue.
