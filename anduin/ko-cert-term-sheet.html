KEY FORMULAS

Key Formulas — Programme-Level

The deterministic formulas published in the base prospectus. Per-Series parameters (Reference Venue, Contract Size, Barrier at issuance, MMB%, Carry Settlement cadence) are fixed in the Final Terms. Worked-example numbers below use BTC as illustration; the same formulas apply across all asset classes (crypto perp reference; spot or perp reference for metals / equities / commodities; venue-published probability for prediction markets).

F1. Certificate Value

The value of an Unlimited Knock-Out Certificate at any point in time is:

Long certificate: Certificate Value = (Reference Price − Knock-Out Barrier) × Contract Size Short certificate: Certificate Value = (Knock-Out Barrier − Reference Price) × Contract Size Where: Reference Price = the Series' Reference Price as defined in §3.1 / §3.1quinquies (crypto: venue perp mark price; metals/equities/commodities: 24/7 perp where available, else spot; prediction markets: Kalshi/Polymarket probability quote) Knock-Out Barrier = fixed at issuance per Series, adjusted at each Carry Settlement per F3 Contract Size = 1 / Multiplier (fixed in Final Terms) e.g., Multiplier 1,000 → Contract Size 0.001 BTC per cert

F2. Implied Leverage and PnL

Implied Leverage (current, live) = Reference Price ÷ (Reference Price − Barrier) PnL per 1-unit move in underlying = ± Contract Size × (1 unit) Worked example (long, BTC at USD 102,400, Barrier USD 92,160, cs 0.001): Certificate Value = (102,400 − 92,160) × 0.001 = USD 10.24 Implied Leverage = 102,400 / (102,400 − 92,160) = 10.0× PnL per USD 1 move = 0.001 × 1 = USD 0.001 per certificate (equivalent to holding 0.001 BTC)

Implied leverage drifts continuously as the Reference Price moves — identical to a perp position. The Series identifier encodes the Barrier, not the leverage (see Series Naming, F6).

F3. Barrier Adjustment — Carry Passthrough

At each Carry Settlement of the Series, the Barrier is adjusted to exactly mirror the carry cost (or credit) the issuer pays (or receives) on the hedge for that Series. Cadence and rate source are set per-Series in the Final Terms and follow the asset class (see Term Sheet "Carry mechanism" row).

At each Reference Venue carry settlement (crypto: typically every 8h; TradFi perp hedge: every 8h on the perp venue; TradFi spot/futures fallback: daily; prediction markets: typically zero carry): For long certificates (issuer is long on the Reference / Hedge Venue): New Barrier = Previous Barrier + (Carry Rate × Reference Price at settlement) For short certificates (issuer is short on the Reference / Hedge Venue): New Barrier = Previous Barrier − (Carry Rate × Reference Price at settlement) Where Carry Rate is: Crypto perp Series → the Reference Venue funding rate Non-crypto perp-hedged Series → the perp-venue funding rate (preferred) Non-crypto spot/futures Series → ESTR/SOFR ± dividend yield or roll yield Prediction-market Series → typically zero; venue platform fee if any Sign convention: positive Carry Rate = longs pay shorts (the typical case). Bidirectional: a negative Carry Rate moves the long Barrier downward (Certificate Value increases — holder receives carry benefit).

F4. Knock-Out Event — Residual Value (Standard Calibration)

If the Reference Price equals or breaches the current Barrier (for long: from above; for short: from below), the Series terminates immediately. Holder receives:

Standard Calibration: Residual Value = max(0, (Reference Price at KO − Barrier at KO) × Contract Size) (short Series: signs reversed) In practice, for highly leveraged Series under Standard Calibration, the residual on a clean barrier-hit is zero or near-zero.

F5. Knock-Out Event — MMB Calibration (Perp-Parity)

The optional MMB Calibration brings the certificate's user experience into exact parity with perp liquidation mechanics: the Barrier is set at the point of zero-equity, and the holder additionally receives a fixed Maintenance Margin Buffer (MMB) cash payment on KO — mirroring how a perp exchange returns the maintenance margin remnant on liquidation.

MMB Calibration: Barrier at issuance = Reference Price × (1 − 1/Leverage) (zero-equity barrier — same algebraic relationship as Standard Calibration) Series Notional Value = Reference Price at issuance × Contract Size MMB Amount = MMB% × Series Notional Value (typical MMB% = 0.3% to 1.0%, fixed per Series) At KO event: Residual Value to holder = max(0, (Reference Price at KO − Barrier at KO) × Contract Size) + MMB Amount Worked example: 10× long BTC; Reference Price USD 102,400; Barrier USD 92,160: Contract Size = 0.001 BTC Notional Value = USD 102.40 MMB% = 0.5% MMB Amount = USD 0.512 per certificate Standard Calibration residual on KO (clean barrier hit): max(0, (92,160 − 92,160) × 0.001) = USD 0.000 MMB Calibration residual on KO: max(0, (92,160 − 92,160) × 0.001) + USD 0.512 = USD 0.512 The MMB Amount is the deterministic floor on the residual value at KO.

F7. Add-Margin Mechanism

Holders may deposit additional collateral to move the Barrier further from the Reference Price — reducing implied leverage and reducing the probability of KO. The issuer simultaneously deposits matching margin into the hedge so the hedge alignment is preserved.

Top-up of ΔC USDC by holder (long Series): New Barrier = Previous Barrier − (ΔC / Contract Size / Number of Certificates) Implied Leverage falls accordingly; KO probability falls. The mechanism is the only top-up mechanism offered; no continuous margin management, partial close-out, or cross-margining. See Q6 on CFD-reclassification analysis of the add-margin mechanism.

F8. Calendar Restrike — Dated PM Series (new in v5.2)

Applies only to dated PM Series with a Calendar Deleveraging Schedule (Term Sheet row above). At each pre-disclosed timestamp in the Schedule, the Series undergoes an in-place NAV-preserving Calendar Restrike Event. S4. Transferable Token Model — Ondo / xStocks Approach (Tokens Distributable w/o KYC)

The intended transfer model follows the approach pioneered by Ondo Finance (USDY, OUSG) and xStocks (tokenized equities): KYC is required to receive tokens directly from the issuer; once in circulation, tokens may be freely transferred between any wallet addresses on-chain — including unregistered wallets — without per-transfer KYC. The restriction applies at the point of issuance (issuer → user), not at the point of secondary transfer (user → user). This is the programme-level "tokens distributable w/o KYC" principle in the Term Sheet.

Transfer restriction model — issuer-gated at issuance, free in secondary: Issuer → User: KYC required. Only KYC-verified wallet addresses may receive tokens directly from the issuer (primary issuance / primary-market purchase). Smart contract enforces: issuer mint/transfer only to whitelisted addresses. User → User (secondary market): Transfers PERMITTED to any wallet address, including non-whitelisted. No smart contract restriction on peer-to-peer secondary transfers. The token is freely transferable once it leaves the issuer. Compliance maintained via: - KYC at primary issuance (AML/CFT check at point of first sale) - Issuer can freeze/blacklist specific addresses (sanctions compliance) - On-chain transfer history is publicly auditable - No ongoing KYC obligation for secondary-market transfers This mirrors how bearer securities work in traditional finance: Bearer bond issued to identified first holder; subsequent transfers between third parties are not gatekept by the issuer.

This model maximises secondary-market liquidity and concentrates the compliance burden at the issuance gate (the point the issuer controls). Ondo Finance has operated this model since 2023 across multiple jurisdictions without regulatory intervention. The key question is whether EU AML/CFT (AMLD6, MiCA, Transfer of Funds Regulation) imposes stricter obligations on secondary transfers than the US framework under which the Ondo precedent developed.

S8. Token-Only Issuance — CFD Reclassification Risk?

If we issue products exclusively as security tokens (on DLT) and do not list them on any EU-regulated MTF or RM, does this affect their classification as "transferable securities" under MiFID II and under the CFD intervention?

For equity / commodity underlyings, the German Turbo precedent is uncontroversial. For crypto specifically, if ESMA were to review an unlisted, OTC-traded leveraged token with crypto exposure, there is a non-zero risk of scrutiny of the transferable-security classification — and, if reclassified, the 2× retail crypto-CFD cap would bite.
